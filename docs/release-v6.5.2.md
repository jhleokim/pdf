# v6.5.2 — 자동 가리기 최적화 3차 검수

자동 가리기의 탐지, 대용량 적용, 실제 PDF 저장을 서로 다른 세 관점에서 검수했다. 추가 OCR 모델·탐지 API·외부 문서 전송은 도입하지 않는다. 원본 대조와 페이지별 확인, 실제 부분 삭제, 검색 텍스트 정리 절차를 유지한다.

## 1차: 탐지 계산과 최악 입력

라벨과 값 사이에 긴 공백이 있으면 정규식이 같은 공백 조합을 반복해서 검사하는 문제를 수정했다. 계좌·이름·주소의 선택적 콜론 처리를 묶어, 기존에 인정하던 라벨·구분자·실제 값의 인식은 유지한다. 정상 OCR 응답뿐 아니라 60,000자에 이르는 음성 입력을 반복 검사한다.

59,000자 공백이 있는 계좌·성명 음성 입력은 같은 Windows 호스트에서 최대 약 4초에서 2ms 미만으로 줄었다. 이는 잘못 합쳐진 OCR·교정 입력의 최악 사례이며 일반 문서 전체 처리 시간이 수천 배 빨라졌다는 뜻은 아니다.

수백~수천 후보가 하나의 OCR 영역에 잘못 합쳐진 입력은 글자폭 계산에 약 21초까지 걸릴 수 있었다. 페이지당 측정에 넘기는 문자 수를 제한하여 과도한 계산은 명시적으로 중단한다. 한도를 넘었을 때 부정확한 좌표로 바꾸거나 일부 후보를 성공 결과로 돌려주지 않는다. 이 합성 입력의 중단까지 걸린 시간은 수정 후 최대 약 110ms였으며, 실제 OCR 응답 10쪽은 Canvas 글자폭 측정을 포함해 full/partial 각각 기대 후보 58개가 모두 일치했다.

## 2차: 대용량 적용·취소·실행 취소

484쪽에 페이지당 500단어가 있는 OCR 데이터를 이용한다. 개인정보를 검색층에서 제거하기 위한 준비와 기록 크기 계산을 한 번에 실행하던 구간을 나누고 중간 취소를 확인한다. 문서 변경 확인 및 최종 반영의 원자성은 유지한다. UI 상태 검사는 실제 소스를 VM 환경에서 실행하며, 실제 PDF 렌더링 메모리나 물리 모바일 기기를 대신하는 검사가 아니다.

썸네일·보드 애니메이션·OCR 일괄 처리 관련 22개 검사도 통과했다. 5,000페이지 메타데이터를 사용하는 썸네일 검사에서는 래스터 캐시가 24쌍 이내로 유지되며, 중간 취소와 재개 시 완료한 OCR 결과를 재사용한다.

484쪽×500단어의 최종 측정에서 탐지 구간은 약 7.44초에서 0.71초, 최종 동기 적용 구간은 약 670ms에서 135ms로 줄었다. 중간 양보 때문에 전체 적용 시간 자체는 환경에 따라 늘 수 있다. 최종 OCR 내용의 정확한 일치 검사는 그대로 남겨 적용 중 문서가 바뀐 경우 이전 초안을 저장하지 않는다.

## 3차: 실제 PDF 부분 삭제와 산출물

변경하지 않는 페이지마다 진행률 알림과 타이머 대기를 반복하던 저장 경로를 시간 예산 단위로 묶는다. 최종 진행률은 반드시 알린다. 전체 메타데이터 정리, 가린 영역의 실제 삭제, 두 단계 안전 저장과 불필요한 PDF 객체 정리는 생략하지 않는다.

실제 PDF 엔진으로 검색 텍스트와 JPEG 보존, 가린 텍스트 제거, 페이지 전체 래스터화 여부를 검사한다. 웹과 단독 HTML은 같은 소스에서 다시 생성하고 배포된 HTML·엔진 자산의 해시를 확인한다.

| 같은 합성 PDF의 저장 경로 | v6.5.1 | 수정 후 |
| --- | ---: | ---: |
| 100쪽, 한 페이지 가리기 | 4.90초 | 0.44초 |
| 500쪽, 가리기 없음 | 8.11초 | 0.58초 |
| 500쪽, 한 페이지 가리기 | 24.69초 | 2.34초 |
| 500쪽, 25페이지에 분산 가리기 | 24.66초 | 2.45초 |

Node 환경에서 실제 PDF-lib·MuPDF 저장 경로를 호출한 수치다. 500쪽 원본은 약 428KB의 합성 디지털 PDF이며, 대용량 스캔 사진 문서의 처리 시간을 대표하지 않는다. 한 페이지 가리기는 3회 추가 실행에서도 약 2.17~2.42초였다. OCR 호출·다운로드·브라우저 렌더링 시간은 포함하지 않는다.

## 남은 한계

실행 취소의 마지막 작업은 기록 예산보다 크더라도 보존한다. 484쪽×500단어의 적용 전·후 OCR 기록은 합쳐 약 96.8MiB로 추정되며, 원본 PDF와 픽셀 메모리는 별도로 필요하다. 따라서 모바일에서 수백 쪽의 OCR·편집·실행 취소를 무제한 보장하지 않는다.

v6.5.1에서 확인한 Paddle 한국어 부분 가리기의 보존 예정 글자 추가 삭제 표본 3건은 별개의 인식 좌표 한계다. 이번 속도 개선으로 해결됐다고 간주하지 않으며 원본 대조와 경계 조절이 필요하다. 자세한 범위는 [v6.5.1 검증 기록](release-v6.5.1.md)을 참고한다.

이번 검수의 UI 성능 수치는 Node/VM에서 측정한 이벤트 루프 지연이며, 브라우저 프레임률이나 실제 모바일 메모리 측정값이 아니다.

## 최종 회귀 및 빌드

`node --test --test-concurrency=1 tests/*.test.cjs` 전체 564개 검사가 실패·생략 없이 통과했다. 정상·비정상 OCR, 긴 공백, 글자폭 계산 한도, 취소·준비 중 문서 변경·원자적 반영, 실제 PDF 부분 삭제, OCR 검색층, 단독 실행 자산, 배포 자산 검사를 포함한다. 별도 담당자가 비동기 적용 및 계산 한도 변경을 다시 검토했으며 관련 27개 검사도 통과했다.

웹·단독 HTML·배포 자산 빌드와 Wrangler dry-run을 완료했다. 단독 HTML은 `dist/PDF-Studio-Standalone-v6.5.2.html`이며 SHA-256은 `7c4fe2a14e88070f234ef9619ad02787fa9cf3eadab8eebff4b7119b8adbdd8d`이다. 이번 검수에서 실제 브라우저 클릭/file:// 및 물리 모바일 재검증은 수행하지 않았다.
