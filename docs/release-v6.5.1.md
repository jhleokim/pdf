# v6.5.1 — 자동 개인정보 가리기 오류 수정

## 수정 내용

OCR이 읽은 개인정보가 표에서 누락되거나 스캔의 가림 경계 밖에 글자 획이 남는 문제를 수정한다. 기존 OCR 엔진과 MuPDF 부분 삭제 경로를 유지하며, 탐지에 추가 모델 다운로드나 외부 API를 사용하지 않는다.

- 표의 계좌·성명·주소 라벨과 같은 행에 있는 값을 연결한다. 값 전체가 형식에 맞고 연결이 하나로 정해지는 경우만 후보로 제안하며, 서로 다른 셀의 숫자 조각을 합치지 않는다. 교정에서 삭제한 텍스트는 다시 사용하지 않는다.
- Vision의 라벨·콜론 박스가 조금 겹치는 경우와 기울어진 글줄에서 라벨 연결이 끊기는 경우를 처리한다.
- 가림 좌표 계산에서 문맥에 따른 글자 간격 보정을 끄고, 기울어진 Paddle 글줄의 네 모서리 좌표를 이용한다. OCR 외곽의 작은 획을 포함하되 옆의 보존할 글자 침범을 줄이도록 제한된 여유 폭을 둔다. Canvas 측정이 없을 때 ASCII 폭은 표준 Helvetica의 advance 값을 사용한다.
- 비정상 OCR 텍스트 값으로 자동 탐지 창이 멈추는 대신 전체 OCR을 다시 실행하도록 안내한다.
- 실행 취소 데이터의 크기를 페이지별로 계산한다. 문서 전체 OCR을 하나의 거대한 임시 문자열로 두 번 생성하던 작업을 제거한다.

## 검증 방식

실제 개인정보가 없는 합성 문서만 사용한다. 이전 버전에서 확보한 Paddle·Vision 응답을 회귀 자료로 고정하고, 같은 한글 문서 3쪽을 두 엔진으로 다시 인식한다. 각 페이지에는 주민번호·계좌·카드·전화·이메일·성명·주소 7종이 있으며 일반 글줄, 라벨/값이 나뉜 표, 3도 기울어진 글줄을 포함한다.

Paddle은 배포 모델과 WASM 런타임을 그대로 실행하고 Canvas만 Node 환경으로 대체한다. 외부 네트워크 시도는 0회다. Vision은 운영 웹 API에 시험용 이미지 3쪽을 전송한다. 두 엔진 모두 새 실행에서 21개 값이 21개 후보로 연결됐다. 인식 시간은 Paddle 페이지당 6.607/6.659/6.763초, Vision 7.215/4.022/4.114초다. 모델 준비와 화면 표시 시간은 포함하지 않으며 특정 기기의 단일 측정이다.

고정한 실제 OCR 응답 10쪽의 기대 후보 58개가 모두 일치하며 이 표본에서 추가 후보는 없다. 실제 부분 삭제 및 검색층 삽입 경로로 저장한 24개 PDF에서는 검사 대상 민감정보의 잔여 획과 원래 검색 문자가 남지 않았다. 별도 공개 문구의 검색은 모두 유지됐다. 보존 예정 문자의 추가 삭제는 아래 한계에 별도로 기록한다.

자동 검사는 중복을 제외한 547개 항목을 통과했다. `node --test --test-concurrency=1 tests/*.test.cjs` 전체 실행 546개에 최종 추가된 독립 글자폭 검사 1개를 더했으며, 해당 geometry 묶음 6개도 재실행하여 통과했다. 실패·생략은 없다. 오류 데이터, 잘못된 표 연결, 삭제한 교정 텍스트, 저장 결과, 484페이지 확인·적용·실행 취소 데이터 계산을 포함한다.

20,000단어·표 라벨 100개의 탐지는 약 100ms였다. Vision 실제 응답을 반복한 484페이지(페이지당 76~83단어)의 탐지 계산은 약 78ms였으며, OCR·페이지 렌더링·해시 계산·사용자 검토·파일 저장은 포함하지 않는다. 대용량 PDF 전체 처리 시간이나 기기별 성능 보장 수치가 아니다.

웹·단독 HTML·배포 자산을 빌드했다. 단독 HTML의 SHA-256은 `7a2a91efe941c3e527fd016fea4996dd9e645e2f86adb77015a8c163b18520b6`이다. 버전 대화상자와 소스 링크도 해당 버전으로 생성한다.

## 적용 범위와 한계

후보는 원본 대조와 페이지별 확인 후 적용한다. OCR 자체가 틀렸거나 글꼴·자간·복잡한 배치가 다른 문서에서는 누락·경계 오차가 남을 수 있다. 합성 문서 통과를 모든 문서의 정확도 보장으로 해석하지 않는다.

Paddle의 한국어 일부 남기기에서는 보존 예정 글자가 추가 삭제되는 3건이 남았다. 이름 첫 글자 2곳과 기울어진 계좌번호의 보존부 첫 숫자 1곳이다. OCR이 공백을 생략한 글줄과 기울어진 글자의 겹친 외곽 때문에 발생한다. 이를 감추려고 가림 영역을 일괄 축소하면 민감한 획이 다시 노출될 수 있어 자동 축소하지 않는다. 해당 결과는 `위치 추정 · 경계 확인` 대상으로 원본과 비교하여 경계를 조절하거나 전체 가리기를 선택한다. 이 표본의 full 가리기와 Vision 검사에서는 같은 보호부 손실이 없었다.

페이지 전체를 이미지로 바꾸지 않는다. 겹친 OCR 단어 또는 글줄은 검색층에서 제외하므로, 부분 가리기라도 같은 Paddle 글줄의 안전한 텍스트가 검색에서 빠질 수 있다. 가리지 않은 원본 디지털 텍스트의 검색은 기존 부분 삭제 결과를 따른다.

이번 브라우저 자동 조작 연결은 시간 초과되어 실제 브라우저 클릭, 직접 file:// 실행, 물리 모바일 기기는 재검증하지 못했다. UI 상태 전이와 오류 복구는 자동 검사로 확인한다.
