# PaddleOCR-VL-1.5 브라우저 실문서 재검증

2026-09-12 · 기준 코드 de193f8 · PDF Studio v5.0

## 판정

현재 Community Q4 + WebGPU 구현은 업무용 대체 OCR로 검증되지 않았다. 사용자가 제공한 실제 스캔 계약서의 첫 페이지에서 모델 준비와 GPU 추론은 시작했지만, 페이지 인식 120초 제한 안에 완료하지 못했다. 다운로드 성공이나 토큰 생성은 문서 인식 성공이 아니다. 이전 합성 이미지 시험을 실제 계약서에 일반화한 판단을 철회한다.

## 재현 조건과 범위

- 사용자가 제공한 6페이지 PDF, 약 1.68MB. 문서 원본·이미지·인식 텍스트·메타데이터는 Git에 포함하지 않는다.
- 모든 페이지에 기존 검색 텍스트가 없음을 pypdf로 확인했다. 첫 페이지 이미지 1648×2367, 페이지 약 593×852pt. 1·2페이지를 렌더링해 두 열의 작은 본문, 표, 필기, 인장이 있는 스캔임을 확인했다.
- Windows, RTX 2080 SUPER가 있는 PC, Codex 내장 Chromium 브라우저. 사용자의 다른 브라우저나 기기 전체를 검증한 결과가 아니다.
- 운영 코드와 동일한 `.deploy` 자산을 localhost:8766에서 실행. 입력 문서는 외부 OCR 서버에 전송하지 않았다. 최초 localhost:8765는 모델 자산 경로가 없어 import 실패했으므로 추론 성능 측정에서 제외했다.
- 고정 revision `ebc8e65ff106df8088bbb3f31ce00bf2fccb24b4`, ONNX Runtime Web 1.29.0, Community Q4 vision/decoder, Spotting 작업.

## 실제 관측

| 클릭 후 경과 | Paddle 첫 페이지 상태 |
|---|---|
| 11초 | 모델 준비 이후 페이지 이미지 분석 |
| 25초 | 97토큰 생성 중 |
| 41초 | 273토큰 생성 중 |
| 59초 | 465토큰 생성 중 |
| 86초 | 721토큰 생성 중 |
| 109초 | 945토큰 생성 중 |
| 134초 확인 시 | 페이지 인식 120초 제한으로 실패, 완료 결과 없음 |

134초는 실패를 확인한 시각이며 정확한 종료 순간이 아니다. 120초는 `recognize` 요청에 적용되는 제한으로 초기 준비 시간과 다르다. 위 값은 단일 실행 관측이며 반복 평균이나 다른 기기의 보장 시간이 아니다.

같은 첫 페이지를 Tesseract 한국어+영어/자동 모드로 다시 실행한 결과, 앱의 경과 시간은 41초였고 886단어를 반환했다. 모델 준비와 문서 렌더링을 포함하는 UI 경과 시간이다. 정답 전사나 CER 채점은 하지 않았으므로 반환 성공을 정확도 보장으로 해석하지 않는다. 앞서 전체 6페이지 비교 실행은 2페이지 처리 중 테스트 탭이 닫혀 완료 시간을 확보하지 못했다. 전체 문서 성공률을 6/6이라고 주장하지 않는다.

Google Vision은 사용자가 이 문서에서 수 초 내 완료했다고 보고했다. 이번 재검증에서는 같은 문서를 클라우드로 보내거나 Vision 정확도를 독립 채점하지 않았다. 이전 약 1초 Vision 시험은 별도의 짧은 합성 이미지였으므로 이 표의 동일 문서 비교값으로 사용하지 않는다.

## 확인한 구조적 제한

1. **공식 파이프라인과 다른 구현.** 공식 제품은 문서 분석 파이프라인을 제공한다. 앱은 CPU 추론용으로 소개된 커뮤니티 ONNX 변환본을 직접 WebGPU에 연결했다. 공식 0.9B 모델의 벤치마크 수치가 이 구성의 정확도나 브라우저 속도를 보증하지 않는다.
2. **작은 글씨 축소.** 현재 1,003,520 픽셀 예산에서 이 페이지는 약 812×1176으로 축소된다. 첫 페이지 원본 이미지보다 각 변이 약 절반이다. 작은 본문 정보 손실 위험이 있지만, 그에 따른 오류율은 정답 전사 없이 계산하지 않았다.
3. **순차 생성 병목.** 전체 페이지의 텍스트와 줄 좌표를 한 토큰씩 생성한다. 코드에서 매 토큰 decoder/embedding 실행과 logits 읽기·CPU argmax가 반복된다. 세부 GPU 연산별 프로파일은 확보하지 않았으므로 특정 연산 하나를 확정 병목으로 단정하지 않는다.
4. **두 개의 완료 제한.** 페이지 120초와 출력 1,536토큰 상한이 있다. 이번 실행에서 직접 확인한 실패 원인은 시간 초과다. 출력 상한 도달은 이번 문서에서 관측하지 않았으며, 코드를 통해 확인한 별도의 제한이다. 시간을 늘리는 것만으로 완료나 품질을 보장할 수 없다.
5. **완료 전 전체 결과 미반환.** 종료 토큰과 유효 좌표까지 받아야 완료 결과를 제공한다. 시간 초과 시 중간 토큰은 완성된 OCR 결과가 아니므로 저장하지 않는다. 사용자가 오래 기다려도 아무 결과를 받지 못하는 현상과 일치한다.

## 반영한 변경과 미해결 항목

- 모델 이름에 ‘실험용’을 표시하고, 실제 계약서 시간 초과·업무용 비권장·2분은 완료 예상이 아닌 중단 제한임을 모델 선택 화면에서 알 수 있도록 안내한다.
- 시간 초과 문구에서 사용자의 기기를 원인으로 단정하는 문장을 제거한다. 출력 상한 오류도 완료하지 못한 상태임을 명확히 표시한다.
- 기본 Tesseract와 활성화된 Google Vision은 유지한다. Paddle 실패를 다른 엔진 성공으로 숨기거나 문서를 자동 업로드하지 않는다.
- **Paddle의 처리 속도와 실문서 인식 성공 자체는 해결되지 않았다.** 위 변경은 상태와 안내의 정정이며 성능 개선으로 보고하지 않는다.
- 다음 엔진 수정은 고정된 실문서 세트에서 페이지별 완료율·처리 시간·숫자/조항 보존·좌표 정확도를 확인한 뒤 채택해야 한다. 입력 영역 분할, GPU용 변환, 브라우저용 경량 OCR은 후보이며 이번 작업에서 검증된 해법이 아니다.
