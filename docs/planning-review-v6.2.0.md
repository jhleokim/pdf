# 개선 기획안 검토 · v6.2.0

v5.2.1을 평가한 기획안을 v6.1.2 소스와 대조한 의견입니다. 기획안 전체를 구현했다는 뜻은 아닙니다.

## 수정할 제안

1. **평가 기준을 갱신합니다.** v6.1.1의 영역 단위 마스킹·원본 기준 용량 표시·24개 썸네일 캐시, v6.1.2의 여러 열/한 열 페이지 비율 처리는 이미 반영했습니다. 실제 대용량 문서의 메모리 상한과 응답성은 별도로 측정해야 합니다.
2. **Basic/Pro를 유지합니다.** ‘문서 보정’만으로는 Pro의 OCR, 개인정보 마스킹, 서명 기능을 설명하기 어렵습니다. 기능 이름과 문맥별 도움말로 보완하는 편이 기존 작업 흐름을 유지합니다.
3. **자동 적용과 자동 측정을 구분합니다.** 화면 진입만으로 문서가 바뀌지 않아야 한다는 원칙에는 동의합니다. 하지만 사용자가 기울기 보정을 켰다면 자동 측정을 기본으로 둘 수 있습니다. 모든 자동 옵션을 일괄 제거하면 기존 요구와 충돌합니다.
4. **모드 전환의 변환을 끄기 전에 공유 편집 상태를 정리합니다.** 현재 Pro → Basic은 편집 내용을 PDF에 반영해 넘깁니다. 단순히 이 단계를 없애면 Basic에서 수정 내용이 안 보이는 문제가 돌아옵니다. 원본 출처, 페이지 UID, 보정 상태를 분리하는 구조 개편과 묶어 진행해야 합니다. 첫 문서 이름으로 합쳐지는 출처 표시도 이 단계의 수정 대상입니다.
5. **500KB는 측정 후 조정할 목표입니다.** 필수 라이브러리의 의존성을 먼저 조사하고, 첫 화면과 첫 PDF 열기·첫 편집 시간을 함께 측정해야 합니다. PDF 생성 코드는 저장뿐 아니라 빈 페이지·사진·미리보기에도 쓰이므로 무조건 저장 시점까지 미룰 수 없습니다. 웹은 같은 출처에서 나누어 로드하고, 스탠드얼론은 같은 소스를 단일 파일로 묶어야 합니다.
6. **모바일은 화면 크기에 맞춰 분기합니다.** 작은 휴대폰의 페이지/미리보기/설정 전환은 타당하지만, 폴더블·태블릿에서는 설정과 실시간 미리보기를 함께 보는 선택을 유지해야 합니다.
7. **처리 위치는 짧게, 전송 동의는 구체적으로 표시합니다.** 헤더에 긴 설명을 늘리기보다는 처리 위치 표시와 도움말을 사용하고, 클라우드 실행 전에 서비스와 전송 페이지를 명확히 확인합니다. 확인하지 않은 서버 보관 정책을 단정하지 않습니다.

## 우선순위

- 다음 구조 개선: 원본 출처와 공유 편집 상태, 모드 왕복 시 중복 변환 방지.
- 다음 성능 개선: 실제 계약서로 냉간/캐시 로딩, 첫 페이지 준비 시간, 대용량 스캔 메모리·취소 응답성 측정. 측정 결과에 따라 Worker·지연 로딩 범위 결정.
- 이어서: 모바일 폴더블 배치, 키보드 페이지 조작, OCR 준비/실행/실패 UI와 보안 정책 검증.

## 이번에 구현한 범위

- 기존 밝기 버튼에 Studio/Paper 테마와 Light/Dark/시스템 설정 통합.
- 테마 변경 시 미리보기 재렌더링 제거. 문서 색상·선택·스탬프·저장 내용을 유지.
- 검토 스탬프의 짧은 문구, 얇은 사각 테두리, 직선 화살표, 기본 문구 8개와 펼쳐 보는 추가 문구.
- v6.2.0 웹/스탠드얼론 공통 소스와 검증. 대규모 구조 변경과 OCR 엔진 변경은 이번 범위에 포함하지 않았습니다.
