# v6.4.8 — 레이어 PDF의 Pro 미리보기 복구

## 원인과 수정

v6.4.7의 `OCProperties` 검사로 머리말·꼬리말용 레이어 설정만 있는 일반 보고서까지 차단했다. 사용자가 제공한 484쪽, 69,513,438 bytes PDF에서 Pro 미리보기의 오류를 재현했다. 이 문서는 기본 OFF 레이어가 없는 단일 Header/Footer OCG 설정을 갖고 있다. 파일 손상이나 페이지 수 제한이 이번 오류의 원인은 아니다.

단일 원본에서 서로 다른 페이지를 꺼내는 경우, 하나의 `PDFObjectCopier`로 페이지와 카탈로그의 `OCProperties`를 함께 복사한다. 같은 원본 참조는 같은 대상 참조로 연결하므로 OFF 상태, Usage, OCMD와 페이지 자원의 OCG 연결을 유지한다. 저장 후 목표 용량 결과의 한 페이지를 미리보기로 꺼내는 경로도 같은 처리를 사용한다. 전체 페이지를 이미지로 만드는 우회는 없다.

## 검증

- 실제 PDF의 1·11·12·80·140·242·400·484쪽을 각각 출력해 MuPDF로 재개방했다. 8쪽 모두 원본과 추출 텍스트 및 0.8배 렌더링 픽셀 해시가 일치했다. 원본 파일은 수정하지 않았다.
- 위 8쪽의 페이지 구성·직렬화 시간은 로컬 Node 한 번의 측정에서 1.18~1.67초였다. 원본 파싱을 포함하며 브라우저 표시 전체 시간이나 성능 보장 수치는 아니다. 11쪽 출력은 33,159 bytes로, 69.5MB 문서 전체를 매번 저장하지 않는다.
- 브라우저에서 484쪽 전체를 불러와 11쪽 Pro 미리보기, 페이지 번호 반영, 이미지가 포함된 80쪽 B&W 변환, 484쪽 전환을 확인했다.
- 단독 HTML도 로컬 HTTP로 실행해 같은 원본 전체를 불러온 뒤 11·484쪽 미리보기를 확인했다. 이번에는 기업 보안 정책별 직접 `file://` 실행이나 물리 모바일 기기는 검사하지 않았다.
- 최종 전체 자동 테스트 **451개 통과, 실패·생략 0개** (`node --test --test-concurrency=1 tests/*.test.cjs`). 웹·단독 HTML·배포 자산 빌드 및 변경 파일 검사를 완료했다.
- 합성 PDF 회귀 검사: 머리말·꼬리말 메타데이터, OFF 레이어 표시 보존, 페이지/카탈로그 참조 일치, Form XObject의 OCMD 연결, 부분 저장·순서 변경, 취소, 저장 결과 미리보기. 기존 마스킹·병합·반복 복제의 거부 검사도 유지한다.
- 실제 회사 문서는 로컬 파일 선택으로만 열었다. 문서 및 추출 내용은 외부 OCR, GitHub, 배포 파일에 포함하지 않는다.

## 제한

레이어 문서의 서로 다른 원본 병합, 같은 페이지의 반복 복제 및 개인정보 마스킹은 여전히 안전하게 처리할 수 없어 중단한다. 레이어 표시 상태는 보존하지만 숨긴 내용을 영구 삭제하는 기능과는 다르다. 이번 변경으로 새 마스킹 지원을 주장하지 않는다. 대용량 문서의 전체 메모리 사용 제한과 기존 기능별 제약은 v6.4.6/6.4.7 점검 기록을 따른다. 실제 파일 전체 484쪽의 모든 편집 조합을 검사한 것은 아니다.
