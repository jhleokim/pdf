# v6.4.0 · 문서 구조를 유지하는 압축 개선

## 사용 방법

Pro → 용량 최적화 → 이미지 최적화 사용. 기본 압축 방식은 **텍스트 유지 · 이미지 압축**입니다. 자동 적용은 꺼져 있습니다.

목표 용량(MB)은 선택 입력입니다. 입력한 경우 설정한 품질과 해상도부터 이미지당 최대 3개의 후보를 비교하고, 목표 달성 여부와 실제 바이트 크기를 표시합니다. 후보는 원본에서 각각 생성합니다. 목표를 맞추기 위해 전체 페이지를 이미지로 변환하거나 흑백으로 바꾸지 않습니다. 목표 없이 선택한 프리셋을 그대로 쓸 수도 있습니다.

목표 용량 후보는 초기값 → 해상도 85%·품질 15%p 감소 → 해상도 70%·품질 30%p 감소 순서입니다. 품질 최저 40%, 긴 변 최저 1,200px이며 이미 그보다 작거나 배치 크기에 맞춰 작은 이미지는 확대하지 않습니다. 더 작은 결과만 남기고 목표를 충족하면 다음 후보를 생략합니다. 목표를 못 맞추어도 성공으로 표시하지 않습니다.

단일 페이지로 문서 전체 예산을 추정하지 않도록, 작업 중 미리보기는 프리셋 기준임을 표시합니다. 결과 생성 후에는 검증된 최종 PDF의 해당 페이지를 보여줍니다. 페이지 이동도 최종 파일에 연결되며, 설정 변경 시 다시 계산합니다.

## 알고리즘과 성능

- 이미지 실제 배치 크기를 기존 MuPDF Worker의 읽기 전용 Device로 분석합니다. 페이지 회전, UserUnit, 중첩 Form 행렬을 반영하고 공유 이미지가 여러 곳에서 사용되면 가장 큰 배치 기준으로 해상도를 보존합니다. A4의 긴 변 11.7인치에서 선택한 픽셀 크기에 해당하는 밀도로 계산합니다. 이미지 CTM 처리는 [MuPDF Device 공식 문서](https://mupdf.readthedocs.io/en/1.28.0/reference/javascript/types/Device.html)의 단위 사각형 정의를 따릅니다.
- 동적 양식·주석·레이어·Pattern 또는 큰 문서는 배치 기반 조정을 생략합니다. A4 변환 시 향후 확대 크기를 잘못 추정하지 않도록 기존 픽셀 상한을 사용합니다. 이 경우에도 기존 이미지 압축은 작동합니다.
- 같은 이미지의 중복 객체는 디코딩 전에 통합합니다. 해시로 후보를 찾은 뒤 실제 바이트가 완전히 같은지 비교합니다. 해시 충돌만으로 공유하지 않습니다. 투명도 마스크의 의존 관계는 통합 후 다시 확인합니다.
- 목표 예산에서 압축 불가능한 이미지·문서 구조의 크기를 제외하고 이미지별로 배분합니다. 후보는 원본 이미지에서 매번 만들고 이전 JPEG를 다시 압축하지 않습니다. 원본 래스터 1개와 출력 래스터 1개만 유지합니다. 사용하지 않는 캔버스와 비트맵을 해제합니다.
- 배치 분석은 64MiB 이하, 300페이지 이하, 50,000객체 이하, 이미지 2,000개 이하에서 수행하며 준비 포함 30초가 넘으면 기존 압축 방식으로 돌아갑니다. 기존 16MP 이미지 처리 제한, 순차 작업, 취소, Worker 유휴 종료를 유지합니다.
- 기존 검색 텍스트·벡터·페이지 상자·리소스 참조를 유지하고 이미지 객체만 교체합니다. 보정 없는 압축은 더 큰 이미지나 더 큰 최종 PDF를 채택하지 않습니다. 마스킹 후에는 가리기 전 원본으로 돌아가는 용량 최적화 경로를 금지합니다.
- 새 OCR/AI 엔진이나 서버 압축을 추가하지 않습니다. 기존 MuPDF 자산을 재사용하며 웹은 같은 출처의 엔진 코드만, 스탠드얼론은 내장 바이트만 사용합니다. 사용자 PDF는 외부로 전송하지 않습니다.

## 실제 비교

2026-09-16, 이 PC의 Chromium에서 동일한 입력을 두 알고리즘으로 비교했습니다. 첨부 경로에서 현재 읽힌 계약서는 **6쪽, 1,675,870바이트**, 검색 텍스트가 없는 JPEG 스캔 6개입니다. 이전 대화의 4.46MB 사례와 같은 바이트 파일이라고 단정하지 않습니다.

| 설정 | 이전 v6.3.0 | v6.4.0 | 입력 대비 절감 |
|---|---:|---:|---:|
| 균형 2,400px·82% | 1,661,753 B | 1,661,753 B | 0.84% |
| 균형에서 목표 0.8MB | 기능 없음 | 729,706 B | 56.46% |
| 작은 용량 1,200px·50% | 기존 제공 프리셋 | 399,494 B | 76.16% |

이미 잘 압축된 페이지 전체 스캔은 기본 균형 설정에서 추가 절감이 거의 없습니다. 작은 용량 프리셋의 절감은 새 알고리즘만의 성과로 주장하지 않습니다. 새 목표 설정의 긴 변은 약 1,650px로 내려갑니다. 1·3·6쪽 렌더링을 검토했고 페이지 구성·인장·필기는 유지되지만 작은 글자는 원본보다 부드러워집니다. 낮은 용량을 지정할수록 정밀한 계약서 글자의 선명도에 손실이 있습니다.

배치 기반 압축 시험은 검색 가능한 텍스트와 숨은 OCR, 세 페이지에서 공유/중복된 2,400px 이미지를 사용했습니다. 같은 프리셋에서 **187,157 → 42,456바이트**, 기존 결과보다 **77.32%** 작았습니다. 가장 큰 배치 기준 855px이며 중복 두 객체를 한 번만 디코딩합니다.

이미지 처리 구간은 첫 비교에서 계약서 균형 0.36/0.50초(이전/신규), 목표 1.04초였습니다. 오프라인 시험과 동시 실행 시 목표 1.96초도 측정됐습니다. 전체 파일 읽기·썸네일·저장 검증 시간은 포함하지 않으며, 모바일이나 대량 계약서의 처리 시간을 보장하지 않습니다.

## 검증 범위

- 자동 회귀 검사 346개: 회전·재단·검색층·색상·폰트·마스크·용량 증가 방지·공유 이미지 배치·중복 마스크 의존 관계 포함.
- 웹 압축 통합 15항목, 단독 HTML 통합 11항목: 실제 JPEG 코덱, 바이트 비교, 검색층 유지, 목표 UI, 저장 결과 미리보기/페이지 이동, 마스킹+압축, 취소.
- 외부 HTTP를 차단한 opaque-origin 단독 HTML에서 마스킹·흑백·현재 미리보기·저장·검색층·취소 후 재시도 34항목 통과. 직접 file:// 실행 및 삼성 모바일 실기기 검사는 별도입니다.
- 검토용 계약서와 출력 PDF는 로컬 시험 폴더에만 보관하며 저장소·배포·메일에 포함하지 않습니다.

## 이번에 포함하지 않은 범위

Ghostscript/QPDF 서버 처리, JBIG2, 일반 MuPDF 전체 문서 재작성, 무제한 목표 용량 탐색은 추가하지 않았습니다. 문서를 이미지로 바꾸는 기존 옵션은 사용자가 직접 선택한 경우에만 작동하며 목표 용량 기능은 텍스트 유지 방식에만 적용됩니다.
