# v6.1.1 — 영역 삭제와 편집 화면 개선

2026-09-15 검증. 이 문서는 구현·시험 기록이며 배포 성공 여부는 Cloudflare 배포 기록으로 확인한다.

## 개인정보 영역 삭제

MuPDF 1.28.1의 WebAssembly 엔진을 도입했다. 검은 사각형을 덮거나 페이지 전체를 이미지로 다시 만드는 대신, 지정 영역과 겹치는 글자와 이미지 픽셀을 PDF 내부에서 삭제한다. 같은 페이지의 영역 밖 텍스트·기존 OCR층·벡터를 유지한다. 사용자 지정 `페이지 전체 압축` 옵션은 여전히 명시적인 이미지 변환이다.

입력 양식과 주석의 외형을 먼저 일반 PDF 명령으로 확정한 뒤 삭제한다. 원본 첨부파일·링크·북마크·메타데이터·접근성 대체 텍스트를 제거하고, 사용하지 않는 객체까지 정리하여 새 파일로 저장한다. 원본 위에 증분 저장하지 않는다. 삭제 실패 시 원본으로 돌아가 저장하거나 이미지 변환으로 우회하지 않는다.

벡터가 마스킹 경계를 가로지르면 해당 벡터 객체 전체가 제거될 수 있다. 특수 문서에서 접근성 대체 텍스트에 의존한 검색 표현은 달라질 수 있다. 대체 텍스트와 바이너리 인라인 이미지가 한 스트림에 섞여 안전하게 분석할 수 없으면 오류로 중단한다. 이러한 제약은 모든 PDF를 완전히 동일하게 유지한다는 보장을 의미하지 않는다.

## 용량과 처리 시간

사용자가 제공한 6쪽 스캔 PDF를 로컬에서만 시험했다. 첫 페이지에 두 영역을 가리고, 자동 기울기 보정을 끈 상태에서 Pro 결과 생성·저장·출력 렌더 확인까지 측정했다. 테스트 문서는 공개 저장소와 배포 파일에 포함하지 않는다.

실제 원본은 **1,675,870 bytes**이며 처음부터 검색 텍스트가 없는 스캔 이미지 PDF였다. 이전 화면의 약 4.46 MB는 편집 과정에서 다시 저장한 중간 파일이었다. 이제 전체 원본을 유지한 문서는 원래 입력 파일과 용량을 비교한다.

| 설정 | 이전 방식 재현 | v6.1.1 | 로컬 처리 시간 |
|---|---:|---:|---:|
| 균형, 품질 82 / 긴 변 최대 2400 px | 14,674,667 bytes | 1,696,774 bytes | 약 8.06초 → 2.21초 |
| 작은 용량, 품질 50 / 긴 변 최대 1200 px | 12,933,612 bytes | 390,935 bytes | 약 5.22초 → 0.75초 |

균형 설정은 원본보다 약 1.2% 커진다. 원본 해상도를 키우지 않고 가린 이미지의 인코딩 비용을 허용한 결과다. 작은 용량 설정은 원본보다 약 76.7% 작지만 작은 글자의 화질도 낮아진다. 정확성이 중요한 계약서에 작은 용량을 강제로 적용하지 않는다. 시간은 이 개발 PC의 단일 실행 측정이며 일반 성능 보장이 아니다. 두 번째 실행은 엔진과 삭제 결과 캐시가 준비된 상태다.

## 성능 설계

- 실제 영역 삭제가 필요할 때만 엔진을 초기화한다. 웹에서는 같은 출처의 해시 고정 자산을 내려받고, HTML 단독 버전에서는 내장 자산을 읽는다. 원본 문서를 전송하지 않는다.
- 전용 Worker에서 문서 하나씩 처리하고 ArrayBuffer를 전송한다. 취소·제한 시간 초과 시 Worker를 종료하며, 30초 미사용 시 WASM 메모리를 회수한다.
- 삭제된 문서 바이트만 1건, 최대 24 MiB까지 메모리에 캐시한다. 영역·순서·회전·마크업 변경 시 무효화하며, 처리 도중 변경된 결과는 새 설정의 캐시로 등록하지 않는다. 문서를 비우거나 마스킹을 모두 지우면 캐시도 비운다.
- 마스킹으로 새로 생긴 이미지에만 색 공간 정규화를 적용해 기존 이미지 압축기를 재사용한다. 영향을 받지 않은 JPEG는 재사용 가능하며, PDF 전체 재래스터화를 하지 않는다.
- 디지털 텍스트만 있는 페이지는 불필요한 재인식을 건너뛴다. 스캔 페이지는 가린 픽셀로 로컬 OCR을 수행한 뒤 사용자가 확인한 검색층을 추가한다.
- 보이는 썸네일과 제한된 주변 캐시를 유지한다. 기존 24개 LRU 정책을 유지하고 가로·세로 비율 정보는 캔버스를 해제한 뒤에도 남긴다.

## UI

Basic 도구에서 수정 구름 오른쪽에 화살표를 추가했다. 드래그 방향대로 그려지며 양 끝점을 각각 움직일 수 있다. 수평·수직·역방향과 실행 취소를 지원하고 PDF에는 벡터로 저장한다.

도구 막대의 아이콘과 간격을 정리하고 선 종류는 작은 선택 메뉴로 바꿨다. 사용 중인 도구에 필요한 속성만 보여준다. 화살표는 선 설정만 제공하며 불투명하게 그린다. 채움 불투명도는 도형의 면에만 적용한다.

가로 페이지 썸네일은 실제 페이지 비율을 사용하고 카드가 세로 페이지 높이까지 늘어나지 않는다. Pro 페이지 맞춤은 가로·세로·회전 페이지가 모두 표시 영역에 들어오는지 검증했다.

우측 하단 버전은 v6.1.1이며 클릭하면 AGPL 전문과 프로젝트·엔진 소스 링크가 열린다. 프로젝트 코드의 LICENSE와 제3자 고지를 함께 제공한다.

## 검증

- Node 회귀 시험 327개 통과: 글자 일부 삭제, 영역 밖 글자·벡터 유지, 가려진 픽셀 삭제, 변경 없는 JPEG 바이트 유지, 원본 양식 값·첨부파일·작성자·숨은 ActualText 삭제, 잘못된 영역 거부 포함.
- 브라우저 문서 무결성 37개: PDF 회전 90/180/270도, CropBox, UserUnit, 마스킹·양식 겹침, 82쪽 썸네일 캐시 등.
- 실제 PP-OCRv5와 Tesseract 검색 PDF 38개: 공개 숫자와 한글 유지, 비공개 텍스트 제거, 중복 OCR 방지, 교정 반영, 마스킹 변경 후 이전 OCR 거부, Pro→Basic 일치.
- 취소·즉시 재시도·캐시 재사용·처리 도중 변경 방어·외부 통신 없음: 스탠드얼론과 웹 자산 로딩 경로에서 각각 7개.
- 화살표 방향·끝점 편집·취소/Undo·벡터 저장·혼합 방향 페이지·도구 막대: PC와 390×844 모바일 뷰포트에서 각각 6개.

스탠드얼론은 네트워크 연결을 `blob:`/`data:`로만 허용한 로컬 브라우저 시험에서 OCR와 영역 삭제를 실행했다. 이 검증은 직접 `file://` 탐색을 허용하지 않는 도구 환경에서 진행되었으므로 `file://` 직접 실행 시험과 구분한다. 엔진 부트스트랩은 중첩 blob import 없이 하나의 Worker에 코드와 WASM을 전달하도록 구성했다.

## 재현

```sh
npm ci
npm run build
npm run build:standalone
npm test
node tests/create-v52.cjs dist/PDF-Studio-Standalone-v6.1.1.html tests/fixtures/native-regression.html
node tests/create-privacy-search.cjs dist/PDF-Studio-Standalone-v6.1.1.html tests/fixtures/native-search.html
node tests/create-v611.cjs
python -m http.server 8765 --bind 127.0.0.1
```

각 `tests/fixtures` HTML을 로컬 브라우저에서 연다. 웹 로딩 경로는 `privacy-lifecycle-web.html`이다. 실제 문서 크기를 비교할 때는 `node tests/create-privacy-size.cjs "로컬 PDF 경로" dist/PDF-Studio-Standalone-v6.1.1.html`을 사용한다. 생성된 시험 파일을 배포하거나 커밋하지 않는다.
