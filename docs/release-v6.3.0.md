# v6.3.0 · 기획안의 점진적 반영

v5.2.1 기준 기획안과 `planning-review-v6.2.0.md`의 반박을 현재 코드에 대조했습니다. 색상·테마·Basic/Pro 이름과 PDF 처리 엔진을 유지하면서 적용할 수 있는 부분을 반영했습니다.

## 이번 변경

- **원본 출처:** 페이지의 원본 문서 ID·파일명·원래 페이지 번호·종류·색상을 현재 편집 PDF와 분리했습니다. Pro 결과를 Basic으로 넘긴 뒤에도 카드와 문서 정보에는 각 원본이 표시됩니다. Undo도 출처를 복원합니다. 원본 PDF 바이트를 추가 복제하지 않습니다.
- **저장 이름:** 한 문서는 `원본명_편집본`, 여러 문서는 `통합_편집본`, 빈 페이지만 있으면 `새문서`를 제안합니다. 빈 페이지를 끼워도 실제 원본이 한 개이면 원본명을 사용합니다. 사용자가 정한 이름은 두 모드에서 공유하고, 문서 전체 초기화 시 지웁니다. Pro 결과에는 페이지 수와 적용 작업 요약을 표시합니다.
- **키보드와 순서:** Enter로 선택, Space로 선택 전환, 방향키로 포커스 이동, Shift로 범위 선택, Alt+방향키로 선택 페이지 묶음 이동을 지원합니다. 삭제 후 인접 페이지에 포커스를 둡니다. 선택 상태를 실제 버튼의 `aria-pressed`로 제공합니다. ‘순서 변경’ 버튼에서 앞으로·뒤로·이동 후 시작 위치를 사용할 수 있습니다. 실행 취소·다시 실행을 데스크톱/태블릿 상단 및 작은 화면의 페이지 목록에 노출했습니다.
- **작은 화면:** 폭 620px 이하 또는 폭 880px 이하·높이 540px 이하에서 페이지/미리보기/설정을 전환합니다. 넓은 폴더블·태블릿은 기존 미리보기+설정 보기를 유지합니다. 닫기는 페이지 목록으로, 설정의 미리보기 버튼은 현재 페이지로 돌아옵니다. 작은 화면의 설정 수정 중에는 숨은 미리보기를 재계산하지 않고, 돌아올 때 최신 설정을 반영합니다.
- **처리 위치:** 짧은 ‘내 기기 처리’/‘클라우드 OCR · 동의 필요’ 상태를 표시합니다. 자세한 설명은 기존 지연 도움말을 사용합니다. Vision 동의 창에 현재 문서 기준 페이지 범위와 최대 전송 개수, 페이지 이미지 전송, 취소 후 회수 불가를 명시합니다. 서버 보관 기간은 단정하지 않습니다.
- **OCR 준비:** 내장형/웹 최초 준비/실행 코드 준비 상태를 구분합니다. Paddle은 모델 18.2MB와 엔진 포함 43.2MB를 별도로 안내하며 모두 압축 전 자산 크기입니다. 다운로드·인식 진행률, 오류 시 재시도, 확인 후 PDF에 포함하는 기존 절차를 유지합니다.
- **글꼴 지연 로딩:** 웹은 fontkit과 선택한 글꼴만 같은 출처에서 불러옵니다. 파일별 SHA-256 주소·장기 캐시·크기/해시 검증·30초 제한을 적용합니다. 동시 요청은 합치고 실패한 요청은 재시도할 수 있습니다. 스탠드얼론에는 네 글꼴과 엔진을 계속 내장합니다. 572바이트 검색 전용 OCR 글꼴도 계속 내장합니다.

## 크기와 검증

- v6.2.3 HTML: 15,836,293바이트. v6.3.0 HTML: 약 4.6MB. 첫 HTML 약 **71% 감소**. 실제 네트워크 전송 크기나 실행 시간의 같은 비율 감소를 의미하지 않습니다.
- 같은 조건의 gzip 계산: 이전 약 10.05MB → 약 1.67MB. 서버 압축 방식·브라우저 캐시·회선에 따라 실제 전송량은 달라집니다. 전체 초기 다운로드 500KB 목표를 달성했다고 주장하지 않습니다.
- `npm test`: 340개 통과. 원본 출처 보존, 내장/웹 글꼴 로더, 손상·외부 주소 거부 및 실패 후 재시도 검사를 추가했습니다.
- 실제 웹/스탠드얼론 통합: 파일명·Pro 왕복·Undo·키보드/위치 이동·삭제 포커스·검색 텍스트·네 글꼴 준비·외부 요청 여부 확인.
- 390×844, 620×900, 621×900, 768×1024, 844×390에서 화면 전환·미리보기 렌더링·폭 넘침·순서 변경·실행 취소 버튼 검사. 좁은 화면에서는 설정 중 불필요한 미리보기 계산도 검사했습니다.
- 기존 모드 동기화 12개, 글꼴 편집/저장 8개, opaque-origin 스탠드얼론의 마스킹/B&W/검색 텍스트/취소·재시도 34개 회귀 검사 통과.
- 합성 문서를 사용한 Chromium 검사입니다. 실제 삼성 인터넷/모바일 키보드/사내 보안 정책/200명 실사용 부하 검증이나 직접 `file://` 검사로 확대 해석하지 않습니다. 스탠드얼론은 HTTP 연결을 차단하고 로컬 파일과 같은 opaque-origin 조건에서 실행했습니다.

## 유지하거나 별도 단계로 둔 제안

| 항목 | 판단 |
|---|---|
| Basic/Pro 명칭 | 기존 이름 유지. Pro는 보정 외에 OCR·마스킹·서명도 포함합니다. |
| 자동 보정 기본값 해제 | 이미 적용. 이번 회귀 검사에서도 진입 시 압축·기울기·흑백이 꺼져 있음을 확인했습니다. |
| 모든 모드 전환을 순수한 화면 전환으로 변경 | 별도 구조 변경. 지금 Pro→Basic은 편집 효과를 PDF에 반영하고 옵션을 초기화합니다. 새 편집이 없으면 재변환하지 않으며, Undo로 전환 전 편집 상태를 복원합니다. 이 동작을 없애거나 보정 옵션을 영구적으로 재편집 가능하게 만들었다는 뜻은 아닙니다. |
| 실제 PDF.js Worker·점진적 페이지 정보·원본/Undo 메모리 한도 | 별도 단계. 취소/문서 수명주기를 바꾸므로 대용량 실제 문서 측정과 함께 진행해야 합니다. 기존 24개 썸네일 캐시는 유지합니다. |
| PDF 파싱/생성 엔진 전체 지연 로딩·초기 500KB | 별도 단계. 빈 페이지·사진·미리보기에서도 생성 엔진을 사용합니다. 이번에는 사용 전 의존성이 없는 글꼴 자산을 분리했습니다. |
| 저장 창 완전 통합 | 이름/페이지 수/결과 요약을 먼저 일치시켰습니다. Basic 대화상자와 Pro 결과 패널의 구조는 유지합니다. |
| CSP/프레임 정책 전면 적용 | 전 기능·Worker·인쇄·오프라인 배포 경로를 확인한 후 별도 적용. 이번 검증 파일의 네트워크 차단 CSP를 운영 전체 보안 감사로 주장하지 않습니다. |
| 압축 알고리즘 추가 개선 | 기존 이미지 압축·중복 제거·더 작은 후보 선택·영역 단위 마스킹 유지. 이번 릴리스에 목표 용량 탐색이나 이미지 배치 기준 해상도 계산을 새로 구현하지 않았습니다. |

## 재현

```sh
npm run build
node scripts/build-deploy.mjs
npm run build:standalone
npm test
node tests/create-planning.cjs
node tests/create-privacy-standalone.cjs
node tests/create-mode-sync.cjs
node tests/create-font-fixture.cjs
python tests/serve-local.py
```

`http://127.0.0.1:8765/work/planning-qa/web.html`, `opaque.html`, `layout-390.html` 등에서 결과를 확인합니다. `tests/serve-local.py`는 로컬 테스트에서 웹 자산 경로만 `.deploy`로 연결합니다. QA 파일은 `work`/`tests/fixtures`에 생성되며 웹 배포물과 스탠드얼론에 포함하지 않습니다.
