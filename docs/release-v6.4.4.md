# v6.4.4 — 선택한 페이지 저장

Basic과 Pro의 PDF 저장 창에서 **전체 페이지 / 선택한 페이지**를 고를 수 있습니다. 기존 동작처럼 전체 저장이 기본이며, 선택한 페이지의 수와 현재 문서에서의 번호를 표시합니다. 선택이 없으면 선택 저장을 비활성화합니다. 비연속 선택 및 재정렬된 문서도 현재 표시 순서로 저장합니다.

## 처리 방식

- 선택 저장은 해당 페이지 목록만 편집·개인정보 삭제·Pro 처리 경로에 전달합니다. 범위를 바꾸면 이전 작업을 취소하고 종료를 기다린 뒤 다음 작업을 실행해 워커·글꼴·마스킹 캐시의 동시 접근을 줄입니다.
- 도장·OCR·수동 기울기는 페이지 UID로 연결합니다. 페이지 번호는 미리보기와 일치하도록 전체 문서에서의 원래 순번을 유지합니다. 제외한 페이지의 오래된 OCR 결과가 선택 저장을 막지 않습니다.
- 전체 Pro 결과만 기존 인쇄·Basic 전환·미리보기 캐시에 게시합니다. 부분 결과는 저장 창에만 보관하여 전체 문서를 잘못 대체하지 않습니다.
- 파일 준비 후 다운로드 버튼을 누르는 동작은 동기적으로 유지합니다. 재다운로드는 준비한 바이트를 재사용하고, 취소되거나 이전 범위에서 생성된 결과는 다운로드하지 않습니다.
- 새로운 네트워크 호출이나 서버 처리는 추가하지 않았습니다. 웹과 단독 HTML에 공통 코드를 포함합니다.

## 검증

- 직렬 자동 검사 366개 통과. 선택한 페이지의 원래 순번과 OCR UID 연결을 실제 PDF를 생성하고 다시 읽어 확인하는 회귀 검사를 추가했습니다.
- 실제 브라우저의 데스크톱 및 390px 모바일 화면에서 각 9개 통합 검사 통과: 2·5페이지 저장, 순서 변경, 빈 선택 차단, 작업 중 범위 변경, Pro 도장/OCR/번호, 전체 결과 캐시 분리, 제외 페이지의 오래된 OCR, 마스킹 후 검색 텍스트 유지, 화면 배치 및 외부 요청 없음.
- 웹 테스트의 글꼴은 현재 배포 구조에 맞춰 동일 출처 자산을 허용하고 외부 출처 요청은 계속 차단합니다. 기존 텍스트 저장 테스트의 잘못된 파일 이름 복구 조건도 바로잡았습니다.
- 단독 HTML 빌드, 내장 스크립트 파싱, 공통 소스 일치, 클라우드 기능 제외 검사 통과. 이번 작업에서는 브라우저 URL 보안 정책으로 `file://` 직접 실행이 차단되어 단독 HTML 직접 실행 검증을 완료하지 못했습니다.

인쇄와 Pro→Basic 전환은 기존처럼 전체 문서를 사용합니다. 저장 창의 선택 범위는 이 두 기능에 영향을 주지 않습니다.
